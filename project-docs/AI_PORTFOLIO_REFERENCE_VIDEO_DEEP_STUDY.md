# AI Workflow Portfolio V2 — Reference Video Deep Study

## Purpose

This document replaces the earlier assumption that "professional" means only:

- a very large `ERIN WONG` title;
- Swiss typography;
- a full-screen image;
- subtle pointer tilt.

Those elements may still appear, but the four reference videos show that the professional feeling comes mainly from a **coherent interaction system**, not from any one visual style.

The new direction is:

> **Editorial Object Index**
>
> A calm editorial cover in which the approved physical AI Workflow scene acts as the project navigation field. Typography provides identity and hierarchy. A shared project rail explains what is active. Motion is camera-led and state-driven. Clicking an object gives a short focus response, then scrolls to the matching evidence section.

# 1. Reference video 1 — `video_1(11).mp4`

Duration: approximately 59 seconds.

## What happens

### 0–5s — object-led cover

- Black background.
- A central hanging keyring object is the strongest visual.
- Small navigation and small labels sit far away from the object.
- The cover does not explain everything immediately.
- The object itself acts as the site identity and category system.
- The tags rotate or change relationship subtly, making the object feel active.

### 5–6s — editorial transition

- A yellow editorial card appears as the selected object/category response.
- The transition is not a generic fade to another page.
- The physical/object motif transforms into an editorial panel.
- A texture/background change helps establish a new mode.

### 6–19s — About page as layered information field

- Large "About me" typography establishes hierarchy.
- Experience, skills, portrait, biography and contact information sit in overlapping panels.
- Panels do not all look like equal cards.
- Yellow is used selectively as a navigational or active-state colour.
- Content moves through reveal, slide and panel expansion rather than repeated fade-up animations.
- The page feels like one designed composition because every panel shares alignment, scale and motion logic.

### 19–20s — exact return to cover

- The site returns to the same object-led index.
- This creates a stable mental model: the cover is the hub.

### 20–24s — photography index

- A physical hanging tag appears at the left.
- A black image panel expands from a compact strip into a larger gallery.
- The transition preserves the category identity.
- The user sees category → preview → project, not category → unrelated page.

### 24–31s — project spread

- The gallery opens into a clean editorial project page.
- Photography fills asymmetric columns.
- Text is small and controlled.
- The composition relies on image rhythm, not a grid of repeated cards.

### 31–40s — branding section

- The cover returns again.
- Branding uses a different hanging tag but the same overall system.
- A project index leads into a case-study spread.
- Project media changes while the navigation language remains consistent.

### 40–47s — archive/category selector

- Horizontal category bands overlap.
- Active bands use yellow or darker grey.
- Project images peek out from behind the bands.
- The selector communicates depth and category state without building a literal 3D scene.

### 48–56s — long-form project sequence

- Large media, black fields, editorial captions and alternating proportions.
- The experience feels like a designed publication rather than a software dashboard.

### 56–59s — archive and return

- A dense archive grid appears.
- The final transition returns to the identity object.

## Why it feels professional

1. **A persistent navigation metaphor** — The keyring/tags are not decoration. They organise the whole site.
2. **State continuity** — The user always understands where they came from and how to return.
3. **Motion transforms meaning** — A tag becomes a category; a strip becomes a gallery; a gallery becomes a project.
4. **Editorial variety inside a consistent system** — Different pages have different compositions, but typography, rules, active colour and object motifs remain related.
5. **Hierarchy through contrast, not through quantity** — Very few elements are active at once.

## What to borrow

- A central physical object as the navigation field.
- Project categories connected to visible objects.
- One shared interaction language across all objects.
- A clear return/state model.
- Thin labels, category numbers and editorial rules.
- Media-led project sections.
- Active-state colour used sparingly.
- Transitions that preserve continuity.

## What not to copy literally

- Black/yellow palette.
- Keyring shape.
- Overlapping panels everywhere.
- The exact archive bands.
- Large modal-like transitions if our approved logic is direct scroll.

# 2. Reference video 2 — `video_1(12).mp4`

Duration: approximately 32 seconds.

## What happens

### 0–10s — one coherent 3D room

- A complete desk/room scene is shown from multiple camera angles.
- Camera orbit is smooth and physically consistent.
- Lighting, materials, scale and perspective belong to one world.
- The scene remains recognisable while the camera moves.

### 10–29s — controlled scene refinement

- The same room is refined and viewed from different angles.
- Lighting and colour are adjusted without rebuilding the composition.
- Small objects support the scene's narrative.
- The visual quality comes from coherent camera, light and material, not from excessive UI overlays.

### 29–32s — implementation handoff

- The project repository appears.
- This shows the 3D scene is intended as a real web implementation, not only a render.

## Why it feels professional

1. One camera system
2. One light system
3. One material system
4. Believable physical scale
5. Controlled movement rather than random object animation

## What to borrow

- The idea that all visual elements must share one camera and one atmosphere.
- Camera-led response instead of making every object bounce independently.
- Subtle movement limits.
- A stable scene composition.

## What not to copy now

- Free orbit.
- Large camera rotation.
- Real-time WebGL requirements.
- Independent 3D object behaviour when the current approved hero is one flat image.

# 3. Reference video 3 — `video_1(13).mp4`

Duration: approximately 44 seconds.

## What happens

### 0–3s — restrained branded loading sequence

- A percentage indicator and a simple logo establish anticipation.
- The logo moves into a textured pegboard world.
- The loading sequence is brief and visually connected to the site.

### 3–12s — the home page is an interface-object

- The pegboard is not a background decoration.
- Hanging tags, cards, keyrings and frames are the navigation.
- Different modules have different scales and shapes.
- The composition is dense but still controlled by the pegboard grid.
- Identity, selected work, skills, about and contact are visible as parts of one system.

### 12–16s — About overlay

- The background dims and blurs.
- A black/yellow editorial panel appears in front.
- The panel has a clear active state and close path.
- The overlay feels connected to the board rather than like a generic popup.

### 17–21s — Skills carousel

- A dark panel opens.
- Skill objects are arranged as a horizontal carousel.
- The background remains present but de-emphasised.
- Motion is focused on one task: exploring skills.

### 21–25s — selected work/book interaction

- A book-like project object opens in front of the board.
- The object changes orientation and state.
- The board remains the navigation context.

### 28–37s — strong editorial studio page

- The site transitions to a very minimal white page.
- A large studio statement is placed with strong asymmetry.
- A timeline/project table uses thin rules and controlled spacing.
- The typography is not decorative; it organises the page.

### 38–44s — project presentations

- Project media is shown in a large white panel.
- A coloured metadata side panel changes by project.
- Navigation arrows are consistent.
- Each project has a distinct colour while the presentation system remains fixed.

## Why it feels professional

1. **The home page has a strong concept** — Pegboard = a real organising system.
2. **Every interaction has a state** — Idle, hover, open, active, close, return.
3. **Depth is created through focus** — Background blur/dim + foreground panel.
4. **The site uses two modes well** — Object-based home and clean editorial project pages.
5. **The graphic system survives different project colours** — The frame, typography and controls remain stable.

## What to borrow

- Home as an object index.
- Clear interaction states.
- A shared active-project caption rather than many floating tooltips.
- Background de-emphasis only when a focused state is required.
- Clean editorial inner pages.
- Project-specific media colour inside a stable page framework.
- Small loading/reveal sequence connected to the visual system.

## What not to copy literally

- Pegboard.
- Hanging hardware.
- Rounded browser frame.
- Modal overlays for every project.
- Black/yellow palette.
- The exact carousel.

# 5. Cross-video design grammar

The four references differ visually, but share the same professional grammar.

## 5.1 One strong organising metaphor

- Keyring/tags
- 3D room
- Pegboard
- Desk objects

The metaphor is functional. It organises content.

For Erin's site: **the handmade AI Workflow Starter Pack is the organising metaphor.** The box is the system hub. The surrounding tool piles are project entrances.

## 5.2 Stable context + focused response

The home scene remains understandable while one target becomes active.

For Erin's site:
- the whole hero scene stays stable;
- the selected hotspot gains a small marker/halo;
- a shared project rail updates;
- clicking gives a short camera nudge;
- the page scrolls to the project.

## 5.3 Motion has cause

Good motion answers: What did the user select? Where is the destination? What changed? How can the user continue?

Bad motion is: endless floating; random card bouncing; generic fade-up on every section; large flat-image rotation; scale effects without meaning.

## 5.4 Two reading modes

The references separate spatial/object navigation from editorial/project reading.

For Erin's site: Hero = object index. Below Hero = Swiss editorial evidence pages.

## 5.5 One shared interaction state machine

```text
Idle
→ Discoverable
→ Hover / Focus
→ Selected
→ Camera Nudge
→ Scroll Transition
→ Destination Focus
```

## 5.6 Typography supports the system

Professional typography is not only "large Swiss type". It must identify the person, describe the portfolio, label the active project, organise sections, and never compete with the physical object scene.

# 6. Diagnosis of the prior direction

The earlier canonical prompt was thorough but treated the design as a checklist of visual instructions rather than one interaction composition.

## Problems found

1. **Over-investment in one giant title** — a `164px`/`10.8vw` name risks becoming a poster with an image behind it.
2. **No active-project information system** — floating hotspot labels can clutter the image; a shared rail is more controlled.
3. **Hotspot coordinates may drift** — percentages attached to the Hero rather than a fixed-ratio scene frame break under `cover`/`contain` changes.
4. **Motion was too generic** — scale-pulse-then-scroll is functional but doesn't capture camera-led logic.
5. **"Swiss" treated as surface styling** — thin rules and uppercase alone aren't a system; it must organise identity, navigation, active project, section numbering, evidence, spacing and responsive behaviour.
6. **Too many floating labels** — the image already has many software logos; more labels compound the noise.
7. **No explicit visual approval gate** — static composition, hover/focus, click transition and responsive validation should be reviewed separately, not all at once.

# 7. Revised design thesis — Editorial Object Index

Cover hierarchy:
```text
1. ERIN WONG
2. AI WORKFLOW SYSTEMS
3. Process thinking · Data visualization · Human-reviewed AI workflows
4. Physical AI Workflow object field
5. Active-project rail
6. Navigation and scroll cue
```

`ERIN WONG` stays large and clearly the first read, but must not dominate the whole canvas:
```css
font-size: clamp(64px, 7.8vw, 116px);
line-height: 0.84;
letter-spacing: -0.055em;
```

The scene must sit in a frame that always preserves the source ratio (1366/768), centred and bottom-anchored, so hotspot percentages never drift under responsive resizing.

A single shared active-project rail (not per-hotspot floating tooltips) shows the exact project name — default state, then updates on hover/focus once that gate is built.

See `PORTFOLIO_V2_LIVING_HERO_PROMPT.md` for the full implementation spec and the four approval gates (A: static composition, B: hover/focus, C: click transition, D: responsive/reduced-motion).
