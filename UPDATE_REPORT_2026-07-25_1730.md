Builds on the stable baseline (`UPDATE_REPORT_2026-07-25_BASELINE.md`) and the visual polish pass (`UPDATE_REPORT_2026-07-25_1600.md`).

## Request summary

When a project's "How it works" and/or "View details" is open and the project scrolls out of view, it should tidy itself back to the default clean state — so only the project currently being looked at stays expanded/active.

## Files changed

- `src/hooks/useWorkflowWalkthrough.ts` — added `reset()`; wrapped `start`/`jumpTo`/`reset` in `useCallback` (empty deps — none of them reference any changing outer state, only the always-stable setState functions and their own arguments).
- `src/components/ProjectCard.tsx` — the existing "auto-collapse details on scroll-away" effect now also covers walkthrough state and calls `walkthrough.reset()`.

## Live verification (Puppeteer) — this took a few attempts to get right

First few attempts showed the reset apparently not firing — traced to a **test methodology mistake**, not a code bug: Project 01 sits below Hero + Selected Systems (each full-viewport-height), so clicking its "How it works" button without first scrolling it into view meant the card's own visibility-tracking observer never saw it become visible in the first place (`hasBeenVisible` never flipped true), so the exit-triggered reset correctly never fired — because the card genuinely had never been "seen." Confirmed this with an independent, separately-created `IntersectionObserver` on the same element, which reported `isIntersecting:false` from the very first callback when the page had never been scrolled — proving the element really was off-screen the whole time, not a bug in the app's own observer.

Redone correctly (scroll to Project 01 first, then click, then scroll away):
- `t=300ms` (right after "How it works" click, walkthrough already scrolled into view first): `activeTitle: "Manual trigger"`, `anyActive: true` — correct, step 1 open.
- `t=600ms` (300ms after scrolling to Project 03, well before the next 1800ms autoplay tick — this timing rules out "autoplay just hadn't advanced yet" as an alternative explanation): `activeTitle: null`, `anyActive: false` — reset fired correctly.
- Scrolling back to Project 01 afterward: `anyActive: false`, `anyDone: 0`, `recap: false`, button reads `"How it works ▶"` — fully clean, ready to restart.
- Separately tested "View details" alone (no walkthrough): opened it (`project--collapsed` → `false`), scrolled away, confirmed it re-collapsed (`project--collapsed` → `true`).

Not expected to affect real users; screenshots specifically (not used here) are the known trigger.
